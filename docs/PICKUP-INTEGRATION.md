# חיבור למערכת "איסוף מסניף" — תיעוד

מסמך זה מרכז את כל מה שידוע על החיבור בין מערכת המשלוחים (הפרויקט הזה) לבין מערכת האיסוף מסניף (`branch-pickup-worker`).
עודכן לאחרונה: 19.11.2026 (מעבר לזרימה v2 — התוכנית המלאה ב-`docs/specs/pickup-integration-v2-plan.md` במרחב העבודה של זוהר, מחוץ לריפו).

## 🎯 המטרה

לקוחה שהזמינה באתר ובחרה "איסוף מסניף" — כשהחבילה שלה מגיעה לסניף, הסטייליסטית מאשרת את זה **מתוך מערכת המשלוחים** (אותה אפליקציה שבה היא מאשרת ארגזים מאוריין), והלקוחה מקבלת ממערכת המשלוחים SMS עם לינק לאישור איסוף.

## 🧭 החלטות (מה הוחלט ולמה)

| החלטה | פירוט |
|-------|-------|
| שני תהליכים נפרדים | **ארגזים מאוריין** — הסניף מאשר כמות (קיים, לא משתנה). **חבילות של לקוחות** — הסניף סורק כל חבילה בנפרד. אין קשר בין ארגז אוריין לחבילות שבתוכו. |
| אפליקציה אחת לסניף | הסטייליסטית עובדת רק במערכת המשלוחים. |
| **(19.11) מערכת האיסוף כמעט לא משתנה** | היא ממשיכה להחזיק את ההזמנות (קליטה משופיפיי, מחסן, הערות בשופיפיי). מערכת המשלוחים רק **קוראת** ממנה, ובסוף **מעדכנת** שההזמנה נסגרה. |
| **(19.11) התהליך מול הלקוחה במערכת המשלוחים** | ה-SMS ללקוחה (Flashy) והלינק לאישור איסוף נשלחים ומוגשים ממערכת המשלוחים. כשהבקשה מגיעה ממערכת המשלוחים, מערכת האיסוף **לא** שולחת SMS משלה. |
| סניף 17 (אבנת פתח תקווה) לא פעיל | לא מותאם למערכת האיסוף. |

## 🔄 הזרימה

```
שופיפיי → מערכת האיסוף (הזמנה עם סניף נבחר)
מחסן סורק מדבקה → "בדרך לסניף"                         (באפליקציית האיסוף, ללא שינוי)
סניף מאשר "התקבל" (במערכת המשלוחים)
   → מערכת האיסוף: "מחכה לאיסוף" + הערה בשופיפיי (בלי SMS)
   → מערכת המשלוחים: SMS ללקוחה דרך Flashy עם לינק /p/<הזמנה>.<חתימה>
לקוחה לוחצת "אספתי" בלינק / סניף לוחץ "נמסרה ללקוחה"
   → מערכת המשלוחים שולחת למערכת האיסוף handover → "הושלמה"
```

## 🧱 מה נבנה במערכת המשלוחים (ענף `feature/pickup-orders`, 12.11.2026)

**שרת (`worker/`)**
- `migrations/0003_pickup_branch_map.sql` — עמודה `pickup_branch_id` בטבלת `branches`
- `seeds/map_pickup_branches.sql` — מילוי ההתאמה בין הסניפים
- `src/services/pickup.js` — התקשורת עם מערכת האיסוף
- `src/routes/pickup.js` — ה-API:

| Endpoint | הרשאה | מה עושה |
|----------|-------|---------|
| `GET /api/pickup-orders` | branch, admin | הזמנות "בדרך לסניף" + "מחכות ללקוחה". סניף רואה רק את שלו |
| `POST /api/pickup-orders/:orderNumber/receive` | branch, admin | "התקבל בסניף" → SMS ללקוחה |
| `POST /api/pickup-orders/:orderNumber/handover` | branch, admin | "נמסר ללקוחה" (אם הלקוחה לא לחצה על הלינק) |
| `POST /api/pickup-orders/:orderNumber/resend-sms` | branch, admin | (19.11) שליחת ה-SMS שוב אחרי כשל |
| `GET/POST /p/:token` | ציבורי (החתימה בלינק) | (19.11) דף ללקוחה עם כפתור "אספתי את ההזמנה" |

**נוסף ב-19.11 (v2)**
- `migrations/0004_pickup_notifications.sql` — טבלה שרושמת מתי הסניף אישר, סטטוס ה-SMS (`sent` / `failed` / `no_phone`), ומתי ההזמנה נסגרה ואיך (`customer` / `branch`)
- `src/services/sms.js` — שליחת SMS דרך Flashy
- `src/services/pickupLink.js` — לינק חתום (HMAC) ללקוחה
- `src/routes/pickupPublic.js` — הדף הציבורי ללקוחה

**מסך (`client/`)**
- `src/pages/PickupOrdersPage.jsx` — מסך "הזמנות איסוף": רשימה, סריקה/הקלדה של מספר הזמנה, כפתורי "התקבל" ו"נמסר". מ-19.11 גם: הודעה אם ה-SMS נשלח/נכשל/אין טלפון, תגית SMS ליד כל הזמנה, וכפתור "שלח SMS שוב"

## 🔌 מה מערכת המשלוחים מצפה למצוא במערכת האיסוף

כל הקריאות עם header בשם `X-Internal-Key` (מפתח משותף).

| קריאה | Body |
|-------|------|
| `GET /internal/orders?status=in_transit,waiting_pickup&branch_id=N` | — |
| `POST /internal/orders/:orderNumber/receive` | `{ branch_id, received_by }` |
| `POST /internal/orders/:orderNumber/handover` | `{ branch_id, received_by }` |

> ✅ **18.11.2026:** הצד הזה לא נבנה ב-12.11 (מערכת האיסוף לא נפרסה מאז אוגוסט). נבנה ב-18.11 בענף `branch-pickup-shipping-scan` ב-`btrtrtk/claude-brain` — **עוד לא פרוס**. נבדק מקומית מקצה לקצה מול הענף הזה (רשימה, התקבל, נמסר, סניף שגוי, הזמנה שלא יצאה, הזמנה לא קיימת, מפתח שגוי).
>
> במערכת האיסוף המפתח נקרא `SHIPPING_INTERNAL_KEY` — **אותו ערך** כמו `PICKUP_API_KEY` כאן.
>
> **19.11.2026 — שינוי קטן נוסף (v2)**, בענף `pickup-shipping-sms-handoff` (מבוסס על `branch-pickup-shipping-scan`, commit `fc3ac92`), **עוד לא נדחף ולא פרוס**. השינוי נוגע רק בנתיבים הפנימיים:
> - `GET /internal/orders` ו-`POST .../receive` מחזירים גם `customer_phone`
> - `receive` שמגיע ממערכת המשלוחים **לא שולח SMS**. סריקה מאפליקציית האיסוף עדיין שולחת כמו קודם
>
> נבדק מקומית מקצה לקצה מול מערכת המשלוחים: התקבל, קבלה כפולה, אין טלפון, שליחה חוזרת, לינק מזויף, אישור לקוחה, ונמסר מהסניף. מה שלא נבדק: סניף שגוי (תקלה במסד הבדיקה המקומי) ושליחת SMS אמיתית.

## 📝 פתוח / שלבים הבאים

1. **לפרוס את מערכת האיסוף** מהענף `pickup-shipping-sms-handoff`, שמחליף את `branch-pickup-shipping-scan` וכולל אותו (`npx wrangler deploy` בתיקייה `projects/branch-pickup/cloudflare-worker`). לפני כן לתאם עם אראל ולדחוף את הענף. אחר כך לסנכרן את המפתח בשתי המערכות.
1א. **(19.11) מערכת המשלוחים:** להריץ את מיגרציה `0004` על המסד החי, להגדיר `FLASHY_API_KEY` ו-`PICKUP_LINK_SECRET`, ולפרוס את השרת ואת המסך. ההתחברות של wrangler צריכה להיות לחשבון `edrizohar2@gmail.com`.
2. **סריקה במצלמה באייפון** — המסך משתמש ב-`BarcodeDetector`, שקיים רק בכרום באנדרואיד. להוסיף את הספרייה `html5-qrcode` (עובדת גם באייפון; כבר בשימוש באפליקציית האיסוף).
3. ✅ **באג "סניף שגוי" במערכת האיסוף** — סריקה בסניף הלא נכון שינתה ל-`wrong_branch` גם הזמנה שכבר מחכה ללקוחה. תוקן באותו ענף: מסמנים "סניף שגוי" רק כשההזמנה `in_transit`.
4. **לתקן את הפריסה האוטומטית** בגיטהאב (או למחוק את ה-workflow), כדי שלא יטעה.
5. **בדיקה מקצה לקצה על הזמנת טסט בלבד** — לא על הזמנה אמיתית של לקוחה.
