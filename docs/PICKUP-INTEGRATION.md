עודכן לאחרונה: 19.11.2026 — **פרוס ועובד** (ראו "המצב בסביבת האמת"). SMS ללקוחה **כבוי בינתיים**.

## 🎯 המטרה

לקוחה שהזמינה באתר ובחרה "איסוף מסניף" — כשהחבילה שלה מגיעה לסניף, הסטייליסטית מאשרת את זה **מתוך מערכת המשלוחים** (אותה אפליקציה שבה היא מאשרת ארגזים מאוריין), וכשהלקוחה מגיעה לאסוף — הסטייליסטית לוחצת "לקוחה אספה". שני השלבים נרשמים בשופיפיי עם תאריך ושעה.

## 🧭 החלטות (מה הוחלט ולמה)

| החלטה | פירוט |
|-------|-------|
| שני תהליכים נפרדים | **ארגזים מאוריין** — הסניף מאשר כמות (קיים, לא משתנה). **חבילות של לקוחות** — הסניף סורק כל חבילה בנפרד. אין קשר בין ארגז אוריין לחבילות שבתוכו. |
| אפליקציה אחת לסניף | הסטייליסטית עובדת רק במערכת המשלוחים. |
| **(19.11) מערכת האיסוף כמעט לא משתנה** | היא ממשיכה להחזיק את ההזמנות (קליטה משופיפיי, מחסן, הערות בשופיפיי). מערכת המשלוחים רק **קוראת** ממנה, ובסוף **מעדכנת** שההזמנה נסגרה. |
| **(19.11) התהליך מול הלקוחה במערכת המשלוחים** | ה-SMS ללקוחה (Flashy) והלינק לאישור איסוף נבנו במערכת המשלוחים. כשהבקשה מגיעה ממערכת המשלוחים, מערכת האיסוף **לא** שולחת SMS משלה. |
| **(19.11) SMS כבוי בינתיים** | אין SMS ללקוחה כרגע — הסניף סוגר את ההזמנה בכפתור "לקוחה אספה". הקוד נשאר; להפעלה: `PICKUP_SMS_ENABLED = "1"` ב-`worker/wrangler.toml`, להגדיר `FLASHY_API_KEY` ולפרוס. |
| **(19.11) תיעוד בשופיפיי** | מערכת האיסוף כותבת לציר הזמן של ההזמנה: "הגיעה לסניף…" ו"הלקוחה אספה…" — עם תאריך, שעה ושם העובדת. |
| **(19.11) טלפוני הסניפים — אנדרואיד** | סריקת QR במצלמה עם `html5-qrcode`. ה-QR במדבקה מכיל רק את מספר ההזמנה. |
| סניף 17 (אבנת פתח תקווה) לא פעיל | לא מותאם למערכת האיסוף. |

## 🔄 הזרימה

```
שופיפיי → מערכת האיסוף (הזמנה עם סניף נבחר)
מחסן סורק מדבקה → "בדרך לסניף"                         (באפליקציית האיסוף, ללא שינוי)
סניף מאשר "התקבל" (במערכת המשלוחים — כפתור או סריקת QR במצלמה)
   → מערכת האיסוף: "מחכה לאיסוף" + הערה בשופיפיי עם תאריך ושעה (בלי SMS)
סניף לוחץ "לקוחה אספה"
   → מערכת המשלוחים שולחת למערכת האיסוף handover → "הושלמה"
   → מערכת האיסוף: הערה בשופיפיי "הלקוחה אספה…" עם תאריך ושעה

בעתיד (כש-SMS יופעל): אחרי "התקבל" — SMS ללקוחה עם לינק /p/<הזמנה>.<חתימה>,
והלקוחה יכולה לסגור את ההזמנה בעצמה בלחיצה על "אספתי".
```

## 🧱 מה נבנה במערכת המשלוחים (ענף `feature/pickup-orders`, 12.11.2026)

**שרת (`worker/`)**
- `migrations/0003_pickup_branch_map.sql` — עמודה `pickup_branch_id` בטבלת `branches`
- `seeds/map_pickup_branches.sql` — מילוי ההתאמה בין הסניפים
- `src/services/pickup.js` — התקשורת עם מערכת האיסוף
- `src/routes/pickup.js` — ה-API:

| Endpoint | הרשאה | מה עושה |
|----------|-------|---------|
| `GET /api/pickup-orders` | branch, admin | הזמנות "בדרך לסניף" + "מחכות ללקוחה". סניף רואה רק את שלו |
| `POST /api/pickup-orders/:orderNumber/receive` | branch, admin | "התקבל בסניף" → "ממתינה ללקוחה" (SMS רק כשמופעל) |
| `POST /api/pickup-orders/:orderNumber/handover` | branch, admin | "לקוחה אספה" → ההזמנה נסגרת |
| `POST /api/pickup-orders/:orderNumber/resend-sms` | branch, admin | (19.11) שליחת ה-SMS שוב — מחזיר שגיאה כל עוד SMS כבוי |
| `GET/POST /p/:token` | ציבורי (החתימה בלינק) | (19.11) דף ללקוחה עם כפתור "אספתי את ההזמנה" — לא בשימוש כל עוד SMS כבוי |

**נוסף ב-19.11 (v2)**
- `migrations/0004_pickup_notifications.sql` — טבלה שרושמת מתי הסניף אישר, סטטוס ה-SMS (`sent` / `failed` / `no_phone`), ומתי ההזמנה נסגרה ואיך (`customer` / `branch`)
- `src/services/sms.js` — שליחת SMS דרך Flashy
- `src/services/pickupLink.js` — לינק חתום (HMAC) ללקוחה
- `src/routes/pickupPublic.js` — הדף הציבורי ללקוחה

**מסך (`client/`)**
- `src/pages/PickupOrdersPage.jsx` — מסך "הזמנות איסוף": רשימה, סריקה/הקלדה של מספר הזמנה, כפתורי "התקבל" ו"לקוחה אספה". מ-19.11: כל הזמנה מוצגת שם → טלפון (לחיץ לחיוג) → מספר הזמנה; אייקון מצלמה בשורת החיפוש לסריקת QR (`html5-qrcode`). תגיות והודעות SMS מופיעות רק כש-SMS מופעל.

## 🔌 מה מערכת המשלוחים מצפה למצוא במערכת האיסוף

כל הקריאות עם header בשם `X-Internal-Key` (מפתח משותף).

| קריאה | Body |
|-------|------|
| `GET /internal/orders?status=in_transit,waiting_pickup&branch_id=N` | — |
| `POST /internal/orders/:orderNumber/receive` | `{ branch_id, received_by }` |
| `POST /internal/orders/:orderNumber/handover` | `{ branch_id, received_by }` |

> ✅ **18.11.2026:** הצד הזה לא נבנה ב-12.11 (מערכת האיסוף לא נפרסה מאז אוגוסט). נבנה ב-18.11 בענף `branch-pickup-shipping-scan` ב-`btrtrtk/claude-brain` — **עוד לא פרוס**. נבדק מקומית מקצה לקצה מול הענף הזה (רשימה, התקבל, נמסר, סניף שגוי, הזמנה שלא יצאה, הזמנה לא קיימת, מפתח שגוי).
>
> במערכת האיסוף המפתח נקרא `SHIPPING_INTERNAL_KEY` — **אותו ערך** כמו `PICKUP_API_KEY` כאן.
>
> **19.11.2026 — שינויים קטנים נוספים**, בענף `pickup-shipping-sms-handoff` (מבוסס על `branch-pickup-shipping-scan`, ומכיל אותו), **נדחף ופרוס**. נוגעים רק בנתיבים הפנימיים:
> - `GET /internal/orders` ו-`POST .../receive` מחזירים גם `customer_phone`
> - `receive` שמגיע ממערכת המשלוחים **לא שולח SMS**. סריקה מאפליקציית האיסוף עדיין שולחת כמו קודם
> - הערות בשופיפיי עם תאריך ושעה ב"הגיעה לסניף", והערה חדשה "הלקוחה אספה" ב-`handover`
>
> נבדק מקומית: התקבל, קבלה כפולה, אין טלפון, לינק מזויף, אישור לקוחה, לקוחה אספה. לא נבדק: סניף שגוי (תקלה במסד הבדיקה המקומי), וכתיבת ההערה בשופיפיי האמיתי.
