# חיבור למערכת "איסוף מסניף" — תיעוד

מסמך זה מרכז את כל מה שידוע על החיבור בין מערכת המשלוחים (הפרויקט הזה) לבין מערכת האיסוף מסניף (`branch-pickup-worker`).
עודכן לאחרונה: 18.11.2026.

---

## 🎯 המטרה

לקוחה שהזמינה באתר ובחרה "איסוף מסניף" — כשהחבילה שלה מגיעה לסניף, הסטייליסטית מאשרת את זה **מתוך מערכת המשלוחים** (אותה אפליקציה שבה היא מאשרת ארגזים מאוריין), והלקוחה מקבלת אוטומטית SMS שהחבילה מחכה לה.

## 🧭 החלטות (מה הוחלט ולמה)

| החלטה | פירוט |
|-------|-------|
| שני תהליכים נפרדים | **ארגזים מאוריין** — הסניף מאשר כמות (קיים, לא משתנה). **חבילות של לקוחות** — הסניף סורק כל חבילה בנפרד. אין קשר בין ארגז אוריין לחבילות שבתוכו. |
| אפליקציה אחת לסניף | הסטייליסטית עובדת רק במערכת המשלוחים. מאחורי הקלעים מערכת המשלוחים מעבירה את הפעולה למערכת האיסוף. |
| מערכת האיסוף נשארת "בעלת הבית" | היא מחזיקה את הזמנות האיסוף, שולחת SMS בפלאשי, וכותבת הערה בשופיפיי. מערכת המשלוחים לא שומרת הזמנות לקוחות. |
| סניף 17 (אבנת פתח תקווה) לא פעיל | לא מותאם למערכת האיסוף. |

## 🔄 הזרימה

```
שופיפיי → מערכת האיסוף (הזמנה עם סניף נבחר)
מחסן סורק מדבקה → "בדרך לסניף"            (באפליקציית האיסוף)
סניף מאשר "התקבל"  → "מחכה לאיסוף" + SMS ללקוחה עם לינק   (במערכת המשלוחים)
לקוחה לוחצת על הלינק / סניף לוחץ "נמסר" → "הושלמה"
```

## 🧱 מה נבנה במערכת המשלוחים (ענף `feature/pickup-orders`, 12.11.2026)

**שרת (`worker/`)**
- `migrations/0003_pickup_branch_map.sql` — עמודה `pickup_branch_id` בטבלת `branches`
- `seeds/map_pickup_branches.sql` — מילוי ההתאמה בין הסניפים
- `src/services/pickup.js` — התקשורת עם מערכת האיסוף
- `src/routes/pickup.js` — ה-API:

| Endpoint | הרשאה | מה עושה |
|----------|-------|---------|
| `GET /api/pickup-orders` | branch, admin | הזמנות "בדרך לסניף" + "מחכות ללקוחה". סניף רואה רק את שלו |
| `POST /api/pickup-orders/:orderNumber/receive` | branch, admin | "התקבל בסניף" → SMS ללקוחה |
| `POST /api/pickup-orders/:orderNumber/handover` | branch, admin | "נמסר ללקוחה" (אם הלקוחה לא לחצה על הלינק) |

**מסך (`client/`)**
- `src/pages/PickupOrdersPage.jsx` — מסך "הזמנות איסוף": רשימה, סריקה/הקלדה של מספר הזמנה, כפתורי "התקבל" ו"נמסר"

## 🔌 מה מערכת המשלוחים מצפה למצוא במערכת האיסוף

כל הקריאות עם header בשם `X-Internal-Key` (מפתח משותף).

| קריאה | Body |
|-------|------|
| `GET /internal/orders?status=in_transit,waiting_pickup&branch_id=N` | — |
| `POST /internal/orders/:orderNumber/receive` | `{ branch_id, received_by }` |
| `POST /internal/orders/:orderNumber/handover` | `{ branch_id, received_by }` |

> ✅ **18.11.2026:** הצד הזה לא נבנה ב-12.11 (מערכת האיסוף לא נפרסה מאז אוגוסט). נבנה ב-18.11 בענף `branch-pickup-shipping-scan` ב-`btrtrtk/claude-brain` — **עוד לא פרוס**. נבדק מקומית מקצה לקצה מול הענף הזה (רשימה, התקבל, נמסר, סניף שגוי, הזמנה שלא יצאה, הזמנה לא קיימת, מפתח שגוי).
>
> במערכת האיסוף המפתח נקרא `SHIPPING_INTERNAL_KEY` — **אותו ערך** כמו `PICKUP_API_KEY` כאן.

## 📝 פתוח / שלבים הבאים

1. **לפרוס את מערכת האיסוף** מהענף `branch-pickup-shipping-scan` (מהמק של אראל: `npx wrangler deploy` בתיקייה `projects/branch-pickup/cloudflare-worker`) ולסנכרן את המפתח בשתי המערכות.
2. **סריקה במצלמה באייפון** — המסך משתמש ב-`BarcodeDetector`, שקיים רק בכרום באנדרואיד. להוסיף את הספרייה `html5-qrcode` (עובדת גם באייפון; כבר בשימוש באפליקציית האיסוף).
3. ✅ **באג "סניף שגוי" במערכת האיסוף** — סריקה בסניף הלא נכון שינתה ל-`wrong_branch` גם הזמנה שכבר מחכה ללקוחה. תוקן באותו ענף: מסמנים "סניף שגוי" רק כשההזמנה `in_transit`.
4. **לתקן את הפריסה האוטומטית** בגיטהאב (או למחוק את ה-workflow), כדי שלא יטעה.
5. **בדיקה מקצה לקצה על הזמנת טסט בלבד** — לא על הזמנה אמיתית של לקוחה.
